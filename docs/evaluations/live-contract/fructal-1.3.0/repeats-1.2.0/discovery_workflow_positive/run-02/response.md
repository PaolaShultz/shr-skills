Use **one dashboard request per refund**, with a stable reference that follows it through finance approval and payment. Customers can use that reference to check progress after a timeout, and support can use it to see who owes the next action.

1. **Submit once.** Show the order, refund amount, and approval requirement before the customer selects **Request refund**. Give the draft a stable submission key before sending it. The server uses that key to create the request once and returns the same reference on repeat submissions. If the response times out, preserve the form and show **Check submission status**. Look up the original submission and reuse its key for any retry.
2. **Keep finance approval in email.** When the request is saved, assign it to the Finance queue and send an email with the reference, amount, and reason. Show **Awaiting finance approval** in the dashboard. Record the authorized approver’s decision against that reference. A repeat reply has no additional effect. If email delivery fails, Finance still owns the visible request and can resend the approval email.
3. **Make the next action visible.** Give support a single view with the request status, current owner, next action, and last update. A named reviewer can claim the request from Finance. A denial closes it with a customer-visible explanation. Approval transfers ownership to the team responsible for issuing the refund. If payment times out, that team checks the payment provider’s record before retrying. Show **Refunded** only after confirmation.

**Verification plan.** Simulate a timeout both before and after the server saves a submission, then reopen the dashboard and retry. Each path should preserve the entered details and produce one request reference. Exercise failed email delivery, duplicate approval replies, denial, and a payment timeout after the provider accepts the refund. Check that support can identify the owner and next action at each handoff, that payment requires approval and occurs at most once, and that customers can recover using a keyboard and hear status updates with a screen reader.
