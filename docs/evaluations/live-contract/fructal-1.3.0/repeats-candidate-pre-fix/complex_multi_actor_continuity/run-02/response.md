### Proposed workflow

| Step | Responsible actor and recovery |
|---|---|
| Submit | Show the customer the request details and any billing consequence before explicit confirmation. Assign the submission a stable key before sending it. Atomically associate that key with one request ID and its submitted version. If the response is lost, look up the same submission and return its receipt. If the details differ, show the difference and ask the customer to confirm an amendment. |
| Hand off | The workflow record names one current owner and one next action. The sending team retains responsibility until the receiving service or reviewer accepts the handoff. Record acceptance and the ownership change together. If delivery fails or acceptance is overdue, the sending team sees a recovery task on the same request. Support can identify that team from its console. |
| Review and approve | The compliance reviewer owns the review once accepted and records the finding in a restricted view. If customer input is needed, show a privacy-safe question on the dashboard and return the answer to the same review. The approval service records the authorized decision against the exact request version. A denial ends progression to billing. An amendment affecting approval requires a decision on the amended version. |
| Bill and reconcile | Billing accepts an instruction only for an approved version and uses one operation ID for the intended charge. If its reply is lost, display “Payment outcome pending” and assign reconciliation to billing. Query billing by that ID before any replay. If billing cannot establish the outcome or guarantee duplicate suppression, keep the request pending for reconciliation. Mark payment complete only on billing confirmation. |
| Cancel | Record the customer’s cancellation intent against the existing request and acknowledge receipt immediately. Serialize cancellation with dispatch so a permitted cancellation can stop an unsent instruction. If dispatch may already have occurred, billing owns reconciliation. Show the confirmed outcome and any policy-authorized remedy before describing the request as cancelled or refunded. |

**Resolve competing authority by fact.** The workflow record owns the accepted submission version, current owner, and next action. Compliance owns its finding, the approval service owns its decision, and billing owns the financial outcome. Support can correct routing within its permissions. Each accepted transition records its source, actor, time, request version, and event ID. Duplicate or late deliveries cannot move the request backward. Conflicting source evidence opens a reconciliation task with a named owner and preserves the audit history.

**Give each channel the same account of progress.** The dashboard and support console derive status from the same versioned record, filtered by access rights. Email identifies the update time and links to the authenticated current view. Keep sensitive details, reviewer notes, and payment data out of email and general logs. After reauthentication, return the authorized actor to the same request and step, preserving entered work only in storage permitted by policy. Show pending states and recovery actions in text, announce status changes to screen readers, and keep keyboard focus at the relevant step.

### Verification plan

- **Submission and interruption.** Submit concurrently, lose the receipt, retry after reauthentication, then attempt a retry with edited details. Verify one original request, a recoverable receipt, and explicit confirmation for the amendment. Check that unrelated requests stay unchanged.
- **Handoff and channel disagreement.** Interrupt acceptance, delay email, and deliver older and duplicate events after newer ones. Verify exactly one accountable owner throughout, a visible overdue task, and matching current status in both authorized views. Follow the stale email link back to the current request.
- **Approval and billing.** Exercise approval, denial, amendment, and a charge that succeeds before its response is lost. Verify that only the approved version can reach billing, the uncertain charge remains pending until reconciled, and recovery produces one financial effect.
- **Cancellation, privacy, and accessibility.** Race cancellation against dispatch and verify the displayed result against billing’s record. Walk the recovery paths as each actor, including keyboard-only and screen-reader use. Check focus, announcements, role access, email contents, and the retained audit trail against the approved policies.
