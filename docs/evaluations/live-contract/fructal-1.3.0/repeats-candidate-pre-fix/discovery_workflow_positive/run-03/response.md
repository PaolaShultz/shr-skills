Give each refund request one dashboard record that customers, Finance, and Support can follow from submission through payout. Finance must approve before money moves. I’ve assumed Finance can open the request from an email and record its decision in the dashboard.

1. **Submit once.** Show the amount and the Finance approval requirement before the customer submits. Give the submission a stable reference before sending it. The server uses that reference to create the request once and returns the same record on retry. If the response times out, keep the entered details and show “Checking whether we received your request.” The dashboard checks by reference and can safely retry with that same reference.
2. **Give Finance the next action.** As soon as the system records the request, show the customer its reference and “Awaiting Finance approval.” Assign it to the Finance queue and email a link to the record. Support can see who owns the next action, including the named reviewer once someone claims it. If the email fails, the request stays visible in the queue.
3. **Record the decision and hand off ownership.** Finance approves or declines the amount shown on the record. A decline closes the request with a customer-visible reason. Approval moves it to “Refund processing,” with a designated payments owner. A repeated approval returns the recorded decision. If payout confirmation times out, the payments owner checks the transaction by reference before retrying. Show “Refunded” only after confirmation.

The customer should recover the same reference and details, and Finance should see exactly one request.
