Give each refund request **one dashboard record and one reference number** from submission through payout. Finance must approve the refund before money moves. I’m assuming email can carry a link to the approval screen. If the decision itself must happen by email, record the authorized reviewer’s decision against the same reference.

1. **Submit and recover.** Before submission, tell the customer that Finance will review the request. Save their entries and assign a stable submission key before sending. The server uses that key to create the request once, even if two attempts arrive together. If the response times out, show “Checking whether we received your request.” Reopening the dashboard or choosing **Try again** resumes with the same key and returns the same receipt.
2. **Route to Finance.** The receipt shows the reference number, “Awaiting Finance review,” and “No action needed from you.” The Finance queue owns the request immediately. Email links to that record, and claiming it makes the reviewer the named owner. A missed email leaves the request visible in the queue. Support can look up the reference and see the current owner, time of last action, and next step.
3. **Decide and pay.** An authorized reviewer approves or declines once. A decline closes the request with a customer-facing reason. Approval transfers ownership to refund processing, and the dashboard shows “Approved · payment pending.” Use the request reference to deduplicate payout attempts. If the payment service times out, processing owns the status check before any retry. Show “Refund issued” only after confirmation.

**Verify before rollout.** Drop the submission response after the server saves the request, then retry from two tabs and confirm both return one reference. Suppress the Finance email and have support locate the owner and next step. Exercise approval, decline, and a repeated approval click. Simulate a lost payout response and confirm exactly one payout for the approved request, zero for the declined request, and no change to an unrelated refund. Check that a keyboard and screen-reader user can recover the receipt and identify its status.
