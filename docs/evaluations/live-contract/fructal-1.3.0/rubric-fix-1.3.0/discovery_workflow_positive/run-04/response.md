Give each refund request **one reference from submission through payout**. Use that reference in the dashboard, the Finance approval email, and Support’s view. Finance approval remains required before money moves. The proposal assumes Finance can open a secure approval link from its email.

1. **Submit once.** Show the customer the order, refund amount, and Finance approval requirement before they submit. Assign a stable reference before the first submission attempt. On receipt, the server saves the request and assigns it to the Finance queue in one transaction. The customer sees “Received · Awaiting Finance review” with the reference.
2. **Recover from a timeout.** Preserve the entered details and reference across a refresh. Show “Checking whether we received your request” and look up that reference. If the request exists, open it. If another submission attempt is needed, reuse the reference. The server enforces uniqueness even if both attempts arrive together.
3. **Make the handoff visible.** The email links Finance to the recorded request. Support can search by reference or order and see the current owner, next action, and time of the last update. The Finance queue owns the request until a reviewer claims it. If email delivery fails, the request stays visible in that queue and the notification can be retried. An authorized reviewer records approval or decline once. Reopening the link shows the recorded decision.
4. **Track the payout separately.** Approval hands ownership to the payouts team or service. The dashboard shows “Processing refund” until payment is confirmed, or a customer-facing reason if Finance declined. If the payment service times out, the payouts owner checks the existing transaction before retrying with the same payout reference. Support can tell the customer who is resolving the uncertainty.

**Verification plan.** In a test environment, drop the submission response after the server saves the request, refresh, and retry concurrently. Confirm one request, one reference, and preserved details. Simulate a lost approval email and two reviewers acting together. Confirm Support can identify the owner throughout, only one decision takes effect, and a decline produces no payout. Drop the payout response after payment succeeds and confirm recovery finds the original payment. Check that keyboard and screen-reader users can submit, recover, and read the status, and that a separate legitimate refund on the same order can proceed independently.
