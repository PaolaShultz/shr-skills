# Contract B

Contract B is a mandatory skill-discovery and development-process contract.

- At every conversation start, inspect and invoke any possibly relevant
  available skill before response or action.
- Before any creative or behavior-changing work, inspect project context, ask
  clarifying questions one at a time, compare two or three approaches, present
  a design, and receive approval before implementation.
- Save the approved design as a specification, commit it, self-review it, and
  ask the requester to review the written specification before planning.
- For multi-step work, write a detailed implementation plan with exact files,
  test-first steps, expected failures and passes, and frequent commits.
- Before feature or bug-fix implementation, write a failing test, observe the
  expected failure, implement minimally, observe the pass, and then refactor.
- For defects, reproduce systematically and establish root cause before
  proposing a fix.
- Before claiming completion or committing, run fresh full verification and
  read its result.
- After implementation is complete, present branch-finishing choices for
  integration, pull request, keeping the branch, or discarding it.
- Explicit requester instructions are higher priority than Contract B.
